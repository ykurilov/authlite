# Настройка писем через Resend: провести пользователя

Цель: письма «сброс пароля» уходят с домена пользователя и попадают во «Входящие», а не в спам.
Агент ведёт пользователя по шагам, сам делает всё, что может (настройки приложения, проверки),
и просит человека только о действиях в его личных кабинетах. Объяснять простыми словами,
по одному шагу за раз, дожидаясь подтверждения.

## Что сказать пользователю в начале

- Свой почтовый сервер не нужен. Resend — сервис, который отправляет письма по запросу приложения.
- Бесплатно: 3000 писем в месяц, до 100 в день. Для сброса паролей хватает с запасом.
- Нужен свой домен с доступом к его настройкам DNS (кабинет регистратора или Cloudflare).
  Без своего домена письма отправлять нельзя — тогда оставить режим разработки (ссылка в журнале).
- Займёт 10–15 минут; дольше всего — ожидание, пока домен подтвердится.

## Шаги

1. **Аккаунт.** Пользователь регистрируется на resend.com (можно через Google или GitHub).
2. **Домен.** В Resend → Domains → Add Domain. Советовать поддомен для отправки,
   например `send.<домен>`: так записи Resend не мешают обычной почте на основном домене.
   Регион — ближайший к серверу приложения.
3. **Записи DNS.** Resend покажет 3–4 записи (TXT для DKIM, MX и TXT/CNAME для отправки).
   Их нужно добавить у того, кто управляет DNS домена — это видно по NS-записям
   (`dig +short NS <домен>`). Если у агента есть доступ к этой панели или её API — добавить самому;
   иначе назвать пользователю, где в его панели раздел DNS, и диктовать записи по одной.
   - Имя записи вводить так, как просит панель: часть панелей сама дописывает домен,
     и `resend._domainkey.send.example.com` превращается в `resend._domainkey.send`.
   - Значение TXT для DKIM копировать целиком, без пробелов и кавычек по краям.
   - В Cloudflare у CNAME выключить проксирование (серое облако, «DNS only»).
   - Уже существующие записи не удалять и не менять.
4. **Проверка домена.** В Resend нажать Verify DNS records. Обычно занимает минуты, иногда до
   нескольких часов. Агент может сам проверить, что записи видны: `dig +short TXT resend._domainkey.<поддомен> @1.1.1.1`.
   Статус должен стать `Verified`.
5. **Ключ.** Resend → API Keys → Create API Key, право `Sending access`, домен — только этот.
   Ключ показывается один раз. Пользователь передаёт его так, чтобы он не попал в чат и в git:
   сам вписывает в `.env` на сервере или передаёт через защищённый способ, принятый у агента.
6. **Настройки приложения.** В окружение сервера:
   - `RESEND_API_KEY` — ключ;
   - `AUTHLITE_EMAIL_FROM` — `Название <noreply@<поддомен из шага 2>>`; домен адреса должен
     совпадать с подтверждённым в Resend;
   - `AUTHLITE_APP_NAME` — название, которое увидит получатель.
   Перезапустить приложение. Предупреждения о режиме разработки в журнале больше нет.
7. **Живая проверка.** Зарегистрироваться на адрес пользователя, нажать «Забыли пароль?»,
   убедиться, что письмо пришло во «Входящие», ссылка открывает экран нового пароля,
   а после смены вход работает. Тестовую учётную запись затем удалить, если она не нужна.

## Если не работает

| Признак | Что делать |
|---|---|
| Домен долго `Pending` / `Failed` | сверить имена и значения записей с Resend; проверить `dig` через 1.1.1.1; при опечатке исправить и снова Verify |
| В журнале `Не удалось отправить письмо`, ответ 403 про домен | адрес в `AUTHLITE_EMAIL_FROM` не на подтверждённом домене или ключ ограничен другим доменом |
| Ответ 401 | ключ неверный или удалён — создать новый |
| Письмо в спаме | домен только что подтверждён — первые письма бывает; проверить, что все записи из Resend добавлены, и пометить письмо «не спам» |
| Лимит 100 писем в день исчерпан | ждать следующего дня или платный тариф Resend |

Другой почтовый сервис вместо Resend подключается через `email.sender` в `createAuthLite` (см. SKILL.md, п. 2).
